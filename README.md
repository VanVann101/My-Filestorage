# My-FileStorage

Сбор фото и видео с события от гостей. Гость сканирует QR, открывает страницу,
вводит имя, выбирает файлы — и они уходят **напрямую в Yandex Object Storage**.

Бэкенда нет вообще. Загрузка идёт по подписанной POST-политике, которая
генерируется заранее и лежит в статике рядом со страницей.

```
QR → GitHub Pages (статика) → POST multipart/form-data → Object Storage
```

## Почему без сервера

Секретный ключ в браузер не попадает. В `policy.json` уходит только подпись,
жёстко ограниченная политикой:

- писать можно **только** в бакет с ключом, начинающимся с `<EVENT_ID>/`;
- размер одного файла — не больше `MAX_FILE_MB`;
- подпись действует `POLICY_DAYS` дней и протухает сама (технического потолка
  на срок нет — это просто дата в подписанном JSON, а не presigned URL).

Читать, удалять или перечислять объекты подпись не позволяет — только класть новые.

## Что нужно сделать в Yandex Cloud

1. **Создать бакет** в Object Storage. Класс хранения — стандартный
   (у холодных есть минимальный срок хранения и плата за извлечение — для
   сценария «залил, через месяц выкачал и удалил» они выйдут дороже).

   Чтение должно быть **публичным** — этим пользуется галерея (см. ниже).
   Правильный способ — **bucket policy**, разрешающая `s3:GetObject` и
   `s3:ListBucket` для `*` на весь бакет: она действует сразу на все
   объекты, включая уже загруженные, и не требует трогать ни политику
   загрузки, ни сам процесс аплоада.

   Если в консоли удобнее выставить ACL бакета `public-read` — учтите:
   это открывает **листинг**, но не делает читаемыми уже лежащие внутри
   объекты (их ACL выставляется отдельно и по умолчанию приватный).
   В этом случае объектам, загруженным до включения `public-read`,
   понадобится разовый проход `aws s3api put-object-acl --acl public-read`
   по всем ключам — bucket policy этого не требует.

2. **Создать сервисный аккаунт** и выдать ему роль `storage.uploader` на этот
   бакет — роль на весь каталог не нужна.

   Эта роль включает в себя и чтение, так что тем же ключом вы потом заберёте
   архив. Удалять объекты она не позволяет: подчистить бакет в конце удобнее
   из консоли под своим аккаунтом.

   Публичное чтение для гостей (галерея) эта роль не даёт и не должна —
   оно настраивается отдельно, на уровне самого бакета (bucket policy или
   ACL из шага 1), а не через сервисный аккаунт.

3. **Сделать статический ключ доступа** — получите пару `ключ` / `секрет`.
   Секрет показывается один раз.

4. **Настроить CORS на бакете** — без этого браузер не отправит ни одного файла:

   | Параметр | Значение |
   |---|---|
   | Источники | адрес вашей страницы, например `https://<username>.github.io` |
   | Методы | `POST`, `GET` |
   | Заголовки | `*` |
   | Время кеширования | 3600 |

   `GET` нужен галерее: она делает `fetch()`-запрос списка файлов из JS,
   а такие кросс-доменные запросы CORS проверяет. Сами `<img>`/`<video>`/
   ссылки на скачивание в CORS не упираются — это обычная загрузка ресурса,
   а не запрос из скрипта.

   Если проверяете локально через `npm run dev` — добавьте отдельным правилом
   ещё и `http://localhost:<порт>` с теми же методами `POST`, `GET`.

5. **Проверить, что POST-политика работает** — самая важная проверка, сделайте
   её до всего остального (см. «Проверка перед событием»).

## Локальный запуск

```bash
npm install
cp .env.example .env      # заполнить своими ключами и параметрами
npm run policy            # сгенерирует public/policy.json
npm run dev
```

`public/policy.json` не коммитится: он генерируется при каждой сборке.

## Деплой

GitHub Actions собирает и публикует на Pages при пуше в `main`, а также
**раз в сутки по расписанию** — чтобы подпись не протухла в самый неподходящий
момент. Запустить вручную можно через `workflow_dispatch`.

GitHub отключает `schedule`-крон, если в репозитории 60 дней подряд нет
активности (коммитов, пушей). Если событие далеко впереди и репозиторий
может «залежаться» — держите `POLICY_DAYS` с запасом, чтобы даже
остановившийся крон не подвёл.

В настройках репозитория укажите:

**Secrets** (Settings → Secrets and variables → Actions → Secrets):

| Имя | Что это |
|---|---|
| `YC_ACCESS_KEY_ID` | идентификатор статического ключа |
| `YC_SECRET_ACCESS_KEY` | секрет статического ключа |
| `VITE_ADMIN_PASSWORD` | пароль входа на `/admin.html` (см. «Админ-панель» ниже) |

**Variables** (там же, вкладка Variables) — значения свои, под конкретное
событие и бакет:

| Имя | Что это | Обязательна |
|---|---|---|
| `YC_BUCKET` | имя бакета в Object Storage | да |
| `EVENT_ID` | префикс ключей в бакете | да |
| `EVENT_TITLE` | заголовок на странице | да |
| `VITE_BASE` | `/<имя-репозитория>/`, если Pages на `<username>.github.io/<repo>/` | если применимо |
| `MAX_FILE_MB` | максимальный размер файла, МБ | нет, по умолчанию 2048 (2 ГБ) |
| `POLICY_DAYS` | сколько дней действует подпись | нет, по умолчанию 150 |

В Settings → Pages выберите источник **GitHub Actions**.

## Галерея

`/gallery.html` — вторая страница сайта, доступна по ссылке «Смотреть
галерею» с главной. Без логина и имени показывает всё, что уже загружено
под текущим `EVENT_ID/`, от новых файлов к старым. Работает и после того,
как истёк `expiresAt` у политики загрузки — приём файлов закрывается, но
смотреть/скачивать можно и дальше.

Требует публичного чтения бакета (см. шаг 1 выше) и `GET` в CORS (шаг 4).
Без этого вместо галереи будет понятное сообщение об ошибке, а не пустой
экран или зависшая загрузка.

Два ограничения, которые сознательно не решались:

- **HEIC/HEVC с айфонов не превьюжится нигде, кроме Safari/iOS** — Chrome
  и Firefox (включая Android) не умеют рендерить `.heic` в `<img>`, вместо
  превью гость увидит плашку «нет предпросмотра». Само скачивание при этом
  работает: это просто отдача файла, не рендер.
- **Плитки грузят оригиналы**, не миниатюры — сжимать или ресайзить не из
  чего без бэкенда. Для гостя это трафик: смотреть много крупных фото и
  видео подряд на мобильном интернете может быть небыстро и небесплатно.

## Админ-панель

`/admin.html` — список гостей с чекбоксами: снятая галочка скрывает все
файлы этого гостя из `/gallery.html` (сами файлы при этом не удаляются
и не переносятся, просто отфильтровываются при отрисовке). Нужна, чтобы
убрать из общей галереи тестовые загрузки, не трогая бакет руками.

Вход по паролю из `VITE_ADMIN_PASSWORD` — **это не настоящая защита**,
а барьер ровно на уровне «случайный гость не откроет и не потыкает»:

- пароль зашивается в собранный JS как обычная строка и виден в
  исходниках страницы любому, кто откроет DevTools;
- сохранение списка идёт через ту же презайненную POST-политику, что и
  обычная загрузка файлов гостями — её поля и так лежат в открытом
  `policy.json`. Технически подкованный человек может отправить такой же
  запрос напрямую, вообще не заходя на `/admin.html` и не зная пароль.

Если бакет и репозиторий доверены только своим (см. «Чего здесь
сознательно нет»), для «гости не станут копаться в DevTools» этого
достаточно. Для защиты от намеренного вмешательства — нет: это потребовало
бы настоящего бэкенда с авторизацией, чего в этом проекте принципиально нет.

## Проверка перед событием

Не пропускайте — второго шанса не будет.

- [ ] **POST-политика реально работает.** Соберите проект и загрузите один файл
      с настоящими ключами. Если хранилище отвечает `403` — читайте `<Code>` в
      ответе: `AccessDenied` обычно означает несовпадение полей формы и условий
      политики, `SignatureDoesNotMatch` — проблему с ключами.
- [ ] **CORS настроен.** Симптом отсутствия CORS — запрос падает ещё до отправки
      данных, в консоли ошибка preflight.
- [ ] **Загрузка с реального телефона**, а не только с десктопа: iPhone и Android,
      мобильный интернет, а не домашний Wi-Fi.
- [ ] **Большое видео** — снимите минуту 4K и загрузите её.
- [ ] **Выбор больше 8–10 файлов разом из галереи iPhone.** Системный пикер
      конвертирует HEIC/HEVC перед отдачей странице в отдельном процессе с
      ограниченной памятью — на большой партии (особенно с видео) он может
      зависнуть или упасть ещё до того, как файлы дойдут до вашего кода. Это
      ограничение iOS, а не сайта; страница уже советует гостю выбирать
      партиями поменьше.
- [ ] **Заблокируйте экран** во время загрузки и посмотрите, что будет.
- [ ] **QR сканируется** с бумаги при плохом освещении.
- [ ] **Дата протухания подписи** позже даты события: откройте `policy.json`
      на опубликованной странице и посмотрите `expiresAt`.
- [ ] **Публичное чтение реально работает.** Откройте прямую ссылку на уже
      загруженный файл в приватной вкладке браузера — не залогиненной в
      Yandex Cloud. Должен открыться файл, а не `AccessDenied`.
- [ ] **CORS разрешает GET.** Откройте `/gallery.html` — список должен
      подтянуться без ошибки preflight/CORS в консоли.
- [ ] **Новые файлы видны в галерее** после обычной перезагрузки страницы
      (F5) — список не обновляется сам по себе, только вручную.
- [ ] **Админ-панель работает**: `/admin.html` пускает по паролю из
      `VITE_ADMIN_PASSWORD`, снятая галочка у гостя реально прячет его файлы
      в `/gallery.html` после перезагрузки галереи.
- [ ] **Кнопка «Скачать» работает на телефоне** — iPhone Safari и Android
      Chrome, не только десктоп.
- [ ] **`.heic`-файл показывает плашку «нет предпросмотра»**, а не сломанную
      вёрстку, в Chrome на Android — скачивание при этом всё равно работает.
- [ ] **Ссылки между страницами** («Смотреть галерею» / «Загрузить свои
      файлы») корректно работают на собранной версии (не `npm run dev`),
      с учётом `VITE_BASE`.

## Как забрать материал

Через обычный S3-клиент, напрямую с вашей машины. Ни страница, ни GitHub тут не
участвуют.

```bash
rclone sync yc:<bucket-name> ./event-photos --progress
```

или

```bash
aws s3 sync s3://<bucket-name> ./event-photos \
  --endpoint-url https://storage.yandexcloud.net
```

Конфиг `rclone` для Яндекса: провайдер `Other`, endpoint
`storage.yandexcloud.net`, region `ru-central1`.

Если нужен именно единый zip-файл (а не просто папка на диске) — упакуйте
результат отдельной командой, PowerShell умеет это без сторонних утилит:

```powershell
Compress-Archive -Path .\event-photos -DestinationPath event-archive.zip
```

Через веб-консоль Yandex Cloud скачать бакет архивом нельзя — она отдаёт
объекты только по одному. Массовая выкачка возможна лишь через CLI
(`aws s3`, `rclone`) или S3-клиенты с GUI (CyberDuck, WinSCP).

**Перед удалением бакета:**

1. Сверьте количество файлов и суммарный размер с тем, что показывает консоль.
2. Откройте несколько фото и видео — особенно `.heic` и `.mov` с айфонов.
3. Сделайте вторую копию архива.

Только после этого удаляйте объекты и бакет. Биллинг здесь по факту хранения —
подписки, которую можно «отменить», нет: пока данные лежат, деньги капают.

## Структура в бакете

```
<EVENT_ID>/<имя-гостя-транслитом>/<uuid>_<исходное-имя-файла>
```

Оригинальное имя гостя дополнительно пишется в метаданные объекта
(`x-amz-meta-guest`, в percent-encoding — чтобы кириллица пережила HTTP-заголовки).

## Чего здесь сознательно нет

- **Базы данных.** Что загружено — видно листингом бакета.
- **Мультипарт-загрузки.** Файлы больше `MAX_FILE_MB` отсекаются на клиенте.
  Для гостевых съёмок с телефона этого хватает; для часовых видео понадобился бы
  бэкенд.
- **Защиты от посторонних.** Кто угодно со ссылкой может загрузить файл, пока
  подпись жива, а также увидеть и скачать всё, что уже загружено в бакет —
  чтение публичное. Для события с известным кругом гостей это осознанный
  размен на отсутствие регистрации.
- **Миниатюр и сжатия в галерее.** Плитки грузят оригиналы файлов как есть.
- **Настоящих подписей гостя в галерее.** Показывается только транслит-slug
  из ключа объекта (например `ivan-petrov`), а не введённое кириллическое
  имя — оно есть только в метаданных объекта, которые листинг не отдаёт.
- **Настоящей авторизации в админ-панели.** Пароль `/admin.html` — это UI-барьер,
  а не контроль доступа: он не защищает саму запись в бакет (см. «Админ-панель»).
